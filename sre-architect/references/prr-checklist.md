# PRR — Production Readiness Review

Проверка готовности сервиса к проду. Каждый пункт — с доказательством: файл, конфиг, ссылка или «не найдено».

## Как проводить

1. Собери контекст: критичность, пользовательский путь, нагрузка, зависимости.
2. Пройди чек-лист. Обязательные пункты — те, без которых сервис нельзя выпускать.
3. Дай вердикт: ✅ Готов / 🟡 Готов с условиями / 🔴 Не готов.
4. Для каждого ❌ — обходной путь, срок и владелец.

## Observability (обязательно)

| Пункт | Как проверить |
|-------|---------------|
| SLI/SLO определены для критичных user journeys | документ SLO, ссылка на дашборд |
| Метрики RED собираются | `http_requests_total`, гистограмма задержки в экспортере |
| Логи в JSON с `request_id` | настройка логгера, пример строки |
| Трейсы с сэмплированием | конфиг OTel Collector, доля выборки |
| Дашборды RED/USE | JSON дашборда в репозитории или ссылка |
| Синтетические проверки критичных путей | конфиг blackbox-exporter или внешнего пробника |

## Alerting (обязательно)

| Пункт | Как проверить |
|-------|---------------|
| У алертов есть severity и владелец | правила Prometheus/VictoriaMetrics с labels |
| Нет алертов без runbook | каждый `alert:` имеет ссылку на runbook |
| Burn rate-алерты настроены | правила из `alerting.md` |
| Эскалация задокументирована | документ oncall, схема эскалации |
| Доставка работает | тестовый алерт дошёл до дежурного |
| Можно заглушить и подтвердить | silence в Alertmanager, тест acknowledge |

## Resilience (обязательно)

| Пункт | Как проверить |
|-------|---------------|
| Graceful shutdown по SIGTERM | обработчик сигнала в коде, `terminationGracePeriodSeconds` |
| Таймауты на всех внешних вызовах | настройки клиентов |
| Ретраи с backoff и jitter | конфиг ретраев, лимит попыток |
| Circuit breaker на критичных зависимостях | конфиг breaker |
| PDB для сервисов с 2+ репликами | манифест `PodDisruptionBudget` |
| Поды распределены по нодам | `topologySpreadConstraints` или anti-affinity |
| requests/limits заданы | манифест деплоймента |

## Документация (обязательно)

| Пункт | Как проверить |
|-------|---------------|
| Runbooks на топ-5 отказов | `docs/`, `runbooks/` |
| Схема архитектуры с зависимостями | `docs/`, `assets/` |
| Oncall handoff: кто, где, как | документ дежурств |
| Шаблон postmortem готов | `docs/postmortem-template.md` |

## Тестирование (обязательно для Critical-сервисов)

| Пункт | Как проверить |
|-------|---------------|
| Нагрузочный тест пройден | отчёт с целевым RPS и p99 |
| Chaos-эксперимент (kill pod) пройден | запись эксперимента и результат |
| Восстановление из бэкапа проверено | дата последней проверки, RTO |

## Вердикт

| Вердикт | Когда |
|---------|-------|
| ✅ Готов | все обязательные пункты ✅ |
| 🟡 Готов с условиями | есть ❌, но с обходом и сроком до недели; риск принят владельцем сервиса |
| 🔴 Не готов | есть ❌ без обхода: нет бэкапов, нет probes, нет алертов, нет runbook на критичный отказ |

## Антипаттерны, которые видны на PRR

| Антипаттерн | Почему плохо | Как исправить |
|-------------|--------------|---------------|
| Монолит с общей БД | один компонент падает — падает всё | выделить сервис, изолировать БД |
| Нет таймаутов | медленная зависимость останавливает весь сервис | таймаут на каждом внешнем вызове |
| Ретраи без backoff | после сбоя ретрай-шторм добивает зависимость | exponential backoff + jitter, лимит попыток |
| Нет PDB | при drain ноды уходят все поды сразу | PDB для сервисов с 2+ репликами |
| Алерты на всё | шум, дежурный перестаёт смотреть | алерты от SLO и от отказа |
| Chaos без стоп-условий | эксперимент валит прод | автоматический откат по SLO (см. `chaos.md`) |
| Платный вендор в критичном пути | лицензия не продлевается, сервис встаёт | self-hosted OpenSource |

## Что чаще всего находят

- Алерты на CPU вместо пользовательского эффекта.
- Runbook есть, но в нём шаги, которых нет у дежурного (нет доступа, нет команды).
- PDB есть, но `minAvailable` равен числу реплик — дренаж блокируется навсегда.
- Бэкап настроен, восстановление ни разу не проверяли.
- Трейсы включены на 100% и стоят дороже метрик.
